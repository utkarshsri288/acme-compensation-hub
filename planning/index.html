ACME / Product framing

Salary data that HR can trust.

A focused plan for replacing spreadsheet-driven compensation management with a fast, explainable workspace for a 10,000-person global organization.

MVP planning artifactHR Manager10,000 employeesModular monolith

The job to be done

When I need to answer “who earns what, where, and how does that compare?”, I want to search, inspect, update, and summarize compensation in one place—so I can make decisions without reconciling multiple spreadsheets.

30s
Target time to find and update a record

In the first release

  • Searchable employee directory
  • Salary profile + safe edits
  • Dashboard and group analysis
  • CSV export
  • 10,000-row deterministic seed

Core experience

01 / FindSearch by name, email, country, department, status, or band.
02 / UnderstandSee local salary, annualized comparison, and organization context.
03 / ChangeEdit with validation and an explicit effective date.
04 / ExplainUse analysis, export, and audit events to support the answer.

Architecture decision

React UI → REST API → service/query modules → SQLite. SQL owns filtering, pagination, and aggregation so the browser never becomes the reporting engine. The schema and API boundaries leave a clear path to PostgreSQL, SSO, and managed deployment.

Trust mechanisms

  • Append-only audit events
  • Visible reporting assumptions
  • Local currency retained
  • Deterministic test data

Deliberate non-goals

No payroll execution, taxes, benefits, equity, legal compliance, real-time collaboration, or bulk imports in the MVP. Authentication and production-grade authorization are required before real employee data, but are kept outside this assessment’s core workflow so the salary-management behavior remains easy to evaluate.

How we will know it works

  • Common directory queries stay under 300 ms locally at 10,000 rows.
  • Dashboard totals reconcile with the filtered directory.
  • Core domain and API paths have fast, deterministic tests.
  • A manager can complete the main workflow without spreadsheet gymnastics.

Build sequence

  1. Plan + architecture
  2. Schema + seed
  3. API + tests
  4. UI + integration
  5. Deploy + demo
