01 / Product direction

The job to be done

Help HR answer “who earns what, where, and how does that compare?” without reconciling multiple spreadsheets.

Product promise

ACME Compensation Hub gives HR one reliable place to find an employee, inspect current compensation, make a safe change, and explain organization-level pay patterns.

  • Search and filter before loading records into the browser.
  • Show local salary and annualized USD comparison side by side.
  • Make effective dates and audit history visible at the point of change.
North-star workflow
< 30s

Find an employee, understand the record, and start a validated update.

Performance target
< 300ms

Common filtered directory query at 10,000 records, locally.

Reference notes

Use a dark navigation rail, warm-white canvas, white elevated panels, one green action color, and restrained status colors. Charts are explanatory, not decorative: every visualization must have a clear label, unit, and selected reporting period.

Interaction rules
  • Debounce search by 250 ms.
  • Preserve filters when returning from a profile.
  • Use empty, loading, error, and no-results states.
  • Open a profile in a route-addressable view.
  • Export respects the current filter set.
Safety cue: salary values should be visually distinct from employee identity data and never be hidden behind a hover-only interaction.

05 / Feature scope

Modules and non-goals

The MVP is intentionally narrow enough to finish well and broad enough to demonstrate product thinking.

Dashboard

Headcount, annualized USD payroll, average salary, and country and department insights.

Employee directory

Search, sort, filter, pagination, export, empty/loading/error states, and route-addressable profiles.

Compensation insights

Country/department groupings, salary distribution, currency mix, and salary-band comparisons where data exists.

Deliberately out of scope

Payroll execution, tax calculations, benefits, equity, local legal compliance, bulk imports, notifications, real-time collaboration, and mobile-native apps. SSO and authorization are production prerequisites but not the assessment’s core workflow.

Trust mechanisms

  • Append-only audit events
  • Visible FX assumptions
  • Validated monetary inputs
  • Local currency retained

07 / Multiple UI directions

Three viable web-app designs

All three fit the same product scope. The recommendation is Design A because HR needs both a daily overview and a fast path into employee records.

A / Command center Recommended

Dashboard-first workspace for daily HR operations.

Best for: payroll questions, leadership reporting, quick monitoring.
Trade-off: employee directory is one click away.

B / Directory-first

Table-led experience for teams who update records all day.

Best for: bulk scanning, search/filter workflows, profile edits.
Trade-off: analytics feel secondary.

C / Insights-first

Analysis-led experience for compensation planning.

Best for: pay equity reviews, country/department comparisons.
Trade-off: slower for a single employee update.
08 / Whole architecture

From HR action to persisted audit record

The system is a modular monolith: one deployable product, clear domain boundaries, and no premature microservices.

HR ManagerSearches, reviews, edits
React UIRoutes, forms, charts, query cache
REST APIAuth boundary, serializers, pagination
Domain servicesValidation, annualization, audit
Relational DBEmployees, salaries, history, events

Layer responsibilities

PresentationReact + TypeScript + reusable local components; accessible states and page-level screens.
Server stateTanStack Query; cache keys by filter set, stale/refetch behavior, optimistic UI only where safe.
APIDjango REST Framework; typed serializers, request validation, pagination, CSV export.
DomainSalary service; frequency annualization, FX assumptions, edit rules, append-only audit event.
PersistenceDjango ORM + SQLite for assessment; PostgreSQL migration path with indexes and constraints.

10 / Definition of done

Ready to submit when…

  • HR can search 10,000 seeded employees, open a profile, edit salary data, and see an audit-safe confirmation.
  • Dashboard totals and grouped insights are explainable and reconcile with the directory data.
  • API and UI have meaningful, fast, deterministic tests plus friendly error states.
  • The app is deployed with a documented setup path, repository link, demo video, and incremental commits.
  • Production gaps—SSO, authorization, secrets, TLS, backups, real FX data, and privacy controls—are clearly called out.
